# Архитектура продукта и сайта

## Почему выбран статический Next.js

MVP не использует формы, базу или серверную персонализацию. Статический экспорт создаёт отдельные HTML-файлы для маршрутов и может размещаться на обычном сервере статических файлов. При расширении можно убрать `output: 'export'`, добавить серверный runtime и сохранить компоненты, типы и маршруты.

Выбор рассчитан на три стадии:

1. Локальный статический лендинг.
2. Бесплатное или недорогое статическое размещение.
3. Российский VPS с Node.js, PostgreSQL и Docker при возвращении заявок и CMS.

## Стек

- Next.js 16.2.x, App Router;
- React 19.2.x;
- TypeScript 5.9.x, strict;
- CSS Modules + CSS variables;
- GSAP 3.15.x только для согласованных scroll-сцен;
- Fontsource Variable: Onest + Lora;
- Playwright + axe;
- Node.js 24 LTS.

Tailwind не используется: проекту важнее читаемая авторская CSS-система, сложные коллажи и точечные breakpoint-правила, чем набор utility-классов.

## Информационная архитектура MVP

Маршрут: `/`.

Будущие маршруты, которые не создаются сейчас:

- `/notes`;
- `/notes/[slug]`;
- `/en`;
- `/projects/[slug]` — только если пользователь позже отменит решение об отсутствии страниц кейсов;
- `/privacy` — при подключении форм или аналитики.

## Контентная модель

Данные лежат в `/src/content`. Компоненты не содержат длинных текстов и цен. Пустые коллекции приводят к скрытию секции. Это позволяет управлять сайтом через Claude Code без CMS и не переписывать разметку.

## Развитие до серверной версии

Когда появится бюджет и потребность в заявках:

1. убрать `output: 'export'`;
2. добавить PostgreSQL;
3. добавить серверный endpoint формы;
4. хранить заявки в БД и отправлять уведомление в Telegram;
5. вернуть трёхшаговый бриф как отдельный feature-модуль;
6. подключить российский VPS и Docker Compose;
7. позже добавить CMS, сохранив текущие типы как контракт данных.

Серверные функции не должны заранее имитироваться в статическом MVP.

## Структура репозитория

```text
src/
  app/                 маршруты, metadata, глобальные стили
  components/
    navigation/        desktop/mobile navigation
    sections/          секции лендинга
    ui/                небольшие переиспользуемые примитивы
  content/             данные сайта
  lib/                 типы, ссылки и небольшие helpers
public/
  media/
    hero/              WebM, постеры
    projects/          реальные обложки
docs/                  документация проекта
tests/                 accessibility и smoke tests
```
