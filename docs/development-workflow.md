# Порядок разработки в Claude Code

## Фаза 0 — подготовка

1. Проверить scaffold и зависимости.
2. Запустить `npm install` и базовые проверки.
3. Показать архитектуру, токены и порядок секций.
4. Дождаться подтверждения.

## Поэтапная сборка

Каждый пункт — отдельный цикл согласования и отдельный Git-коммит после принятия.

1. Глобальные токены, layout, шрифты, skip link.
2. Desktop и mobile navigation.
3. Hero.
4. About.
5. Projects.
6. Consultation callout.
7. Proof section и правила скрытия.
8. Services.
9. AI thought + AI product callout.
10. Process.
11. Teaching context + Figma callout.
12. Testimonials и правила скрытия.
13. FAQ.
14. Final CTA и footer.
15. Полный адаптив.
16. Анимационная полировка.
17. SEO metadata и OG assets.
18. Финальный QA.

## Цикл одного блока

1. Прочитать спецификацию блока.
2. Проверить, есть ли реальный контент.
3. Реализовать только этот блок.
4. Запустить проверки.
5. Запустить локальный preview.
6. Передать пользователю ссылку.
7. Остановиться.
8. Внести запрошенные правки в этот же блок.
9. После одобрения создать Git-коммит.

## Коммиты

Формат:

```text
feat(section): implement hero
fix(section): refine project hover behavior
chore(tokens): establish typography and spacing
```

Не коммитить непринятые варианты как финальные. Не переписывать историю Git.

## Поведение при нехватке данных

- Задать один конкретный вопрос.
- Если пользователь отложил контент, использовать предусмотренный placeholder или скрыть секцию.
- Не заполнять паузу творческими догадками.

## Definition of Done MVP

- все принятые блоки собраны;
- все CTA открывают `@poofex`;
- пустые proofs/testimonials скрыты;
- desktop и mobile соответствуют разным правилам движения;
- статический build создаёт `/out`;
- проверки проходят;
- документация соответствует реализации;
- последняя принятая версия отмечена отдельным коммитом.
