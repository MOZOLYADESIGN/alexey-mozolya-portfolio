# MASTER PROMPT — портфолио Алексея Мозоли

Ты работаешь над личным сайтом Алексея Мозоли — дизайнера интерфейсов и бренд-стратега. Сайт должен показывать его способ мышления, отобранные работы и продукты, приводить заказчиков в личный Telegram и постепенно расширяться из лендинга в многостраничный сайт.

## Перед началом

1. Прочитай этот файл целиком.
2. Затем прочитай все документы в `/docs` в таком порядке:

4. До визуальной разработки покажи архитектуру, дизайн-токены и порядок блоков. Дождись подтверждения.

## Главная задача MVP

Создать локально работающий, статически экспортируемый лендинг. Главная воронка: пользователь знакомится с автором, видит портфолио, понимает предложение и переходит в Telegram `https://t.me/poofex`.

Главная конверсия: **портфолио → Telegram**.

Основная аудитория:

- владельцы образовательных и B2C-проектов;
- руководители продукта и маркетинга;
- студии и агентства.

Вторичная аудитория: начинающие графические и веб-дизайнеры.

## Неизменяемые ограничения MVP

- Нет базы данных, бэкенда, API-маршрутов и форм заявок.
- Нет попапов.
- Нет онлайн-оплаты, CRM, календаря и личного кабинета.
- Нет аналитики, cookies и баннера согласия.
- Нет CMS и административной панели: контент хранится в типизированных файлах проекта.
- Нет отдельных страниц кейсов: карточка проекта не открывает кейс.
- Нет тёмной темы.
- Нет WebGL, Three.js и настоящей 3D-модели головы.
- Нет внешнего подключения Google Fonts: шрифты должны поставляться локально.
- Все CTA открывают один обычный диалог `https://t.me/poofex`, без подставленного текста.
- Не придумывай клиентов, результаты, отзывы, цифры, биографические факты и проекты.
- Не используй шаблонный копирайтинг: «уникальные решения», «новый уровень», «индивидуальный подход», «воплощаю мечты» и сходные формулы запрещены.

## Обязательный стек

- Next.js App Router со статическим экспортом `output: 'export'`;
- React;
- TypeScript в строгом режиме;
- CSS Modules и глобальные CSS custom properties;
- GSAP подключается только для согласованных сложных сцен; обычные состояния реализуются CSS;
- локальные шрифты Onest Variable и Lora Variable Italic через Fontsource;
- ESLint, Playwright и axe для проверок;
- без UI-кита и без тяжёлого набора компонентов.

Текущий scaffold уже задаёт совместимые версии. Не обновляй major-версии во время визуальной работы без отдельной задачи.

## Визуальные правила

- Общий фон: еле заметный почти белый серый, ориентир `#F8F8F7`.
- UI монохромный. Насыщенный цвет принадлежит проектам, продуктам и отдельным медиаобъектам.
- Белые карточки: крупные скругления, тонкая граница, очень мягкая тень.
- Система выглядит как управляемый коллаж с перекрытиями на больших экранах.
- На смартфоне коллаж становится последовательной вертикальной лентой без перекрытий.
- Основная типографика: современный гротеск; точечные акценты — контрастная антиква с курсивом.
- Не превращай страницу в набор одинаковых bento-карточек. Текстовые разделы должны дышать и работать редакционно.

## Первый экран

- Крупная типографика.
- Рядом находятся эмоциональная голова автора и яркий абстрактный объект.
- Финальный desktop-asset: два отдельных прозрачных WebM с бесшовной петлёй; голова меняет направление взгляда и иногда подмигивает.
- На смартфоне всегда показывается статичный постер.
- Пока финальных файлов нет: используй портрет из референса и CSS-объект, сохраняя точки замены.
- Никакой белой дымки и растворения головы.

## Навигация

- Большие экраны: верхняя плавающая капсула со всеми разделами и кнопкой Telegram.
- Маленькие экраны: снизу две капсулы — Telegram и бургер; меню выезжает снизу.
- После прокрутки вниз капсулы уменьшаются по высоте примерно вдвое.
- Полная высота возвращается только в начале страницы.
- Hover/active меняют состояние, но не размер.

## Правила разработки

Разрабатывай строго по одному блоку.

После каждого блока:

1. запусти проверки;
2. запусти локальный preview;
3. передай пользователю только ссылку на preview и коротко назови готовый блок;
4. остановись и дождись подтверждения;
5. после подтверждения создай отдельный Git-коммит;
6. только затем переходи к следующему блоку.

Не делай следующий блок «заодно». Не создавай несколько альтернатив без запроса. Не меняй согласованный блок при работе над соседним.

## Обязательные проверки

- TypeScript;
- ESLint;
- production build со статическим экспортом;
- Playwright на целевых viewport;
- axe без critical/serious нарушений;
- Lighthouse;
- клавиатурная навигация;
- desktop и mobile layouts;
- `prefers-reduced-motion`;
- отсутствие горизонтального скролла;
- отсутствие CLS при загрузке медиа.

Целевой уровень доступности: WCAG 2.2 AA.

## Работа с отсутствующим контентом

- Проекты: использовать восемь CSS-градиентных заглушек «Проект 01–08» только в development.
- Пустые блоки отзывов, логотипов и цифр не отображать.
- Не использовать чужие референсы как опубликованный контент.
- Все медиа должны иметь явные размеры/соотношения сторон.
- В контентных файлах оставлять понятные `TODO`, а не фальшивые тексты.
